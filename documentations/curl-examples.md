# cURL Reference — pgfoundation FastAPI public API

Ready-to-run `curl` examples for every route this service exposes, generated by
reading the actual route/schema code (`pgfoundation_api/`), not just the design
docs. See [08 — API Surface](./08-api-surface.md) for the narrative version of
this table and the contracts that back it.

```bash
export BASE_URL=https://pgfoundation.dev.tripleq.ai
export TOKEN=my-shared-secret            # only needed when auth.enabled=true and provider=token
```

## Auth

Auth is **off by default** (`auth.enabled: false`) — every call below works with
no header at all in that mode. When `auth.enabled: true`:

| Provider | How the caller proves identity |
|----------|--------------------------------|
| `token` (`SharedSecretAuthenticator`) | `Authorization: Bearer <token>` — checked as SHA-256 digest, constant-time compare |
| `mtls` (`MeshIdentityAuthenticator`) | A header set by the mesh/ingress (default name `x-client-cert-subject`, config: `auth.mtls.identity_header`) — **never set this yourself over an untrusted hop**, it must be stripped at the edge |

Add `-H "Authorization: Bearer $TOKEN"` to any call below once auth is enabled.
Every response also echoes/generates `X-Request-Id` (send your own via
`-H "X-Request-Id: ..."` to correlate logs; the server will generate one if you
don't).

## 1. Operational endpoints (unversioned — not under `/v1`)

Deliberately unpinned to a version: probes and scrapers shouldn't need editing
the day `v1` retires.

```bash
# Liveness — 200 while the process is up, does NOT touch the database
curl -s "$BASE_URL/health"
# → {"status":"healthy","datasources":{"main":"unknown","analytics":"unknown"}}

# Readiness — runs SELECT 1 per datasource; 503 when every source is down
curl -s -i "$BASE_URL/ready"
# → 200 {"status":"healthy","datasources":{"main":"healthy"}}
# → 503 {"status":"down","datasources":{"main":"down"}}   (note the -i to see the status line)

# Prometheus scrape endpoint (empty body until an exporter is bound)
curl -s "$BASE_URL/metrics"
```

## 2. v1 admin & docs

```bash
# List configured data sources
curl -s "$BASE_URL/v1/datasources" \
  -H "Authorization: Bearer $TOKEN"
# → {"datasources":["main","analytics"]}

# Versioned health/ready aliases (kept for parity with the old Django surface)
curl -s "$BASE_URL/v1/health"
curl -s -i "$BASE_URL/v1/ready"

# OpenAPI document / interactive docs (docs_url is config-gated; off in prod)
curl -s "$BASE_URL/v1/openapi.json"
curl -s "$BASE_URL/docs"
curl -s "$BASE_URL/redoc"
```

## 3. Governed, name-based invocation (the recommended surface)

No SQL ever crosses the wire — you name a view/function/procedure and pass
structured arguments. All bodies accept an optional `"row_format": "dict"|"tuple"`
(defaults to `api.default_row_format`) and an optional `"schema"` field (aliased
internally to `db_schema`).

### 3.1 `POST /v1/datasources/{name}/view` — query a view/table by name

```bash
curl -s -X POST "$BASE_URL/v1/datasources/main/view" \
  -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" \
  -d '{
        "name": "v_paid_orders",
        "schema": "public",
        "columns": ["id", "customer", "amount"],
        "filters": [
          {"column": "customer", "op": "eq", "value": "bob"},
          {"column": "amount", "op": "gt", "value": 10}
        ],
        "order_by": [{"column": "id", "descending": false}],
        "limit": 50,
        "offset": 0
      }'
# → {"rows":[{"id":3,"customer":"bob","amount":"42.00"}],"row_count":1,"elapsed_ms":11.4,"columns":null}
```

Valid `filters[].op` values (closed whitelist):
`eq ne lt le gt ge in not_in like ilike between is_null is_not_null`.

### 3.2 `POST /v1/datasources/{name}/view/stream` — same, at constant memory

Streams NDJSON by default, or SSE with `Accept: text/event-stream`. Use this
instead of `/view` whenever the result may exceed `api.max_response_rows`.

```bash
curl -N -X POST "$BASE_URL/v1/datasources/analytics/view/stream" \
  -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" \
  -H "accept: application/x-ndjson" \
  -d '{
        "name": "readings",
        "filters": [{"column": "day", "op": "eq", "value": "2026-08-13"}],
        "row_format": "tuple"
      }'
# → one JSON object per line; a mid-stream failure ends with
#   {"error":{"type":"...","message":"..."},"partial":true}
```

### 3.3 `POST /v1/datasources/{name}/function` — call a function by name

`args` is either a named mapping or a positional list. Set `"scalar": true` for
a scalar-returning function.

```bash
# Named args
curl -s -X POST "$BASE_URL/v1/datasources/analytics/function" \
  -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" \
  -d '{
        "name": "fn_daily_totals",
        "args": {"day": "2026-08-13"}
      }'

# Positional args, scalar result
curl -s -X POST "$BASE_URL/v1/datasources/main/function" \
  -H "content-type: application/json" \
  -d '{"name": "fn_customer_balance", "args": ["bob"], "scalar": true}'
```

### 3.4 `POST /v1/datasources/{name}/function/stream`

Same shape as 3.3, streamed like 3.2.

```bash
curl -N -X POST "$BASE_URL/v1/datasources/analytics/function/stream" \
  -H "accept: application/x-ndjson" \
  -H "content-type: application/json" \
  -d '{"name": "fn_export_rows", "args": {"day": "2026-08-13"}}'
```

### 3.5 `POST /v1/datasources/{name}/procedure` — `CALL` a stored procedure

`args` is positional; pass `null` for `OUT`/`INOUT` placeholders. Outputs come
back as a row in the response envelope.

```bash
curl -s -X POST "$BASE_URL/v1/datasources/main/procedure" \
  -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" \
  -d '{"name": "sp_debit", "args": ["acct-1", 100]}'
```

### 3.6 `POST /v1/datasources/{name}/interval` — time-bucketed fetch

Half-open `[start, end)` range. `metrics[].func` is whitelisted by the core
compiler (`sum`, `avg`, `count`, `min`, `max`, …).

```bash
curl -s -X POST "$BASE_URL/v1/datasources/analytics/interval" \
  -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" \
  -d '{
        "source": "readings",
        "time_column": "ts",
        "start": "2026-08-13T00:00:00Z",
        "end": "2026-08-14T00:00:00Z",
        "every": "15 minutes",
        "metrics": [{"column": "value", "func": "avg", "alias": "avg_value"}],
        "group_by": ["sensor_id"],
        "tz": "UTC"
      }'
```

### 3.7 `POST /v1/datasources/{name}/interval/stream`

Same body as 3.6, streamed like 3.2.

### 3.8 `POST /v1/datasources/{name}/fetch-since` — resumable keyset page

Never `OFFSET` — pass back the `next_watermark` from the previous response as
the next call's `cursor` to resume exactly where you left off.

```bash
curl -s -X POST "$BASE_URL/v1/datasources/main/fetch-since" \
  -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" \
  -d '{
        "sql": "SELECT id, ts, payload FROM events",
        "params": {},
        "cursor": {"order_by": ["ts", "id"], "after": null},
        "limit": 1000
      }'
# → {"rows":[...],"row_count":1000,
#     "next_watermark":{"order_by":["ts","id"],"after":["2026-08-13T00:14:59Z", 40213]}}

# next page: feed the returned next_watermark back in as `cursor`
curl -s -X POST "$BASE_URL/v1/datasources/main/fetch-since" \
  -H "content-type: application/json" \
  -d '{
        "sql": "SELECT id, ts, payload FROM events",
        "cursor": {"order_by": ["ts", "id"], "after": ["2026-08-13T00:14:59Z", 40213]},
        "limit": 1000
      }'
```

### 3.9 `POST /v1/datasources/{name}/execute-many` — batched parameterized writes

One protocol round trip for many rows; `params_seq` items may be named dicts or
positional lists.

```bash
curl -s -X POST "$BASE_URL/v1/datasources/main/execute-many" \
  -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" \
  -d '{
        "sql": "INSERT INTO events (id, payload) VALUES (%(id)s, %(payload)s)",
        "params_seq": [
          {"id": 1, "payload": "a"},
          {"id": 2, "payload": "b"}
        ]
      }'
# → {"row_count":2,"elapsed_ms":3.1}
```

### 3.10 `POST /v1/datasources/{name}/copy` — streaming `COPY` ingest

```bash
curl -s -X POST "$BASE_URL/v1/datasources/main/copy" \
  -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" \
  -d '{
        "table": "events_staging",
        "rows": [[1, "2026-08-13T00:00:00Z", "a"], [2, "2026-08-13T00:01:00Z", "b"]]
      }'
```

## 4. Advanced / trusted — raw parameterized SQL

**Off by default** (`api.enable_raw_sql: false`). When disabled these routes are
not registered at all — they 404, not 403, and don't appear in `/v1/openapi.json`.
Config refuses to start with this on and `auth.enabled: false` outside the `dev`
profile (ADR-008), so expect these to need `Authorization` in any real
deployment.

### 4.1 `POST /v1/datasources/{name}/query` — raw read

```bash
curl -s -X POST "$BASE_URL/v1/datasources/main/query" \
  -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" \
  -d '{
        "sql": "SELECT id, customer, amount FROM orders WHERE customer = %(customer)s",
        "params": {"customer": "bob"}
      }'
```

### 4.2 `POST /v1/datasources/{name}/query/stream`

Same body as 4.1, streamed like 3.2.

### 4.3 `POST /v1/datasources/{name}/execute` — raw write

```bash
curl -s -X POST "$BASE_URL/v1/datasources/main/execute" \
  -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" \
  -d '{
        "sql": "UPDATE orders SET status = %(status)s WHERE id = %(id)s",
        "params": {"status": "paid", "id": 3}
      }'
# → {"row_count":1,"elapsed_ms":2.0}
```

## 5. Batch — `POST /v1/batch`

One endpoint, three execution strategies selected by `mode`. Every item is
dispatched through the same operations table as the unary routes above, so
`"op"` is one of: `view`, `function`, `procedure`, `interval`, `fetch_since`,
`execute_many`, `copy` (plus `query`/`execute` when raw SQL is enabled). HTTP
stays `200` on partial failure — each item carries its own `status`; only
whole-batch failures (validation, admission, total timeout, or a rolled-back
`transactional` batch) produce a non-`200`.

### 5.1 `parallel` — bounded scatter-gather, independent items, can span data sources

```bash
curl -s -X POST "$BASE_URL/v1/batch" \
  -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" \
  -d '{
        "mode": "parallel",
        "max_concurrency": 8,
        "fail_fast": false,
        "items": [
          {"id": "orders", "datasource": "main", "op": "view",
           "payload": {"name": "v_paid_orders"}},
          {"id": "daily", "datasource": "analytics", "op": "function",
           "payload": {"name": "fn_daily_totals", "args": {"day": "2026-08-13"}}}
        ]
      }'
# → {"mode":"parallel","elapsed_ms":14.2,"ok_count":2,"error_count":0,
#     "results":[{"id":"orders","status":"ok","rows":[...],"row_count":2,"elapsed_ms":6.1},
#                {"id":"daily","status":"ok","rows":[...],"row_count":1,"elapsed_ms":8.0}]}
```

### 5.2 `sequential` — one pinned connection, pipelined, in order

```bash
curl -s -X POST "$BASE_URL/v1/batch" \
  -H "content-type: application/json" \
  -d '{
        "mode": "sequential",
        "items": [
          {"id": "1", "datasource": "main", "op": "view", "payload": {"name": "v_paid_orders", "limit": 1}},
          {"id": "2", "datasource": "main", "op": "view", "payload": {"name": "v_paid_orders", "limit": 2}}
        ]
      }'
```

### 5.3 `transactional` — one UnitOfWork, all-or-nothing, same data source

Retried whole on serialization failure (`40001`/`40P01`) — items must have no
non-database side effects, since the body may run more than once.

```bash
curl -s -X POST "$BASE_URL/v1/batch" \
  -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" \
  -d '{
        "mode": "transactional",
        "items": [
          {"id": "1", "datasource": "main", "op": "procedure",
           "payload": {"name": "sp_debit", "args": ["acct-1", 100]}},
          {"id": "2", "datasource": "main", "op": "procedure",
           "payload": {"name": "sp_credit", "args": ["acct-2", 100]}}
        ]
      }'
```

## 6. Live change feed — `GET /v1/datasources/{name}/subscribe/{channel}`

`LISTEN/NOTIFY` over Server-Sent Events. Unbounded lifetime — pins a connection
for as long as the client stays connected. `-N` disables curl's output
buffering so events print as they arrive.

```bash
curl -N "$BASE_URL/v1/datasources/main/subscribe/orders_changed" \
  -H "Authorization: Bearer $TOKEN" \
  -H "accept: text/event-stream"
# → data: {"channel":"orders_changed","payload":"...","pid":12345}
#
#   (repeats on every NOTIFY; connection stays open until you Ctrl-C or the
#   client disconnects)
```

## 7. Error shape (every non-2xx response)

```json
{"error": "unknown data source 'bogus'", "type": "ConfigError", "request_id": "6f1e..."}
```

| Status | Cause |
|--------|-------|
| 400 | `QueryError` — bad SQL, unsafe identifier, bad filter; or a failed Pydantic validation |
| 401 | `AuthenticationError` (only when `auth.enabled: true`) |
| 403 | `AuthorizationError` (only when `auth.enabled: true`) |
| 404 | `ConfigError` — unknown data source, or a `trusted_only` route while `enable_raw_sql: false` |
| 409 | `IntegrityError` — constraint violation, not retryable |
| 413 | Result exceeds `api.max_response_rows` — message points at the `/stream` variant |
| 422 | Batch exceeds `batch.max_items` |
| 503 | Pool timeout / connection error / transient error / admission limiter shed — carries `Retry-After` |

Example: an unknown data source —

```bash
curl -s -i -X POST "$BASE_URL/v1/datasources/bogus/view" \
  -H "content-type: application/json" \
  -d '{"name": "anything"}'
# → HTTP/1.1 404 Not Found
#   {"error":"unknown data source 'bogus'","type":"ConfigError","request_id":"..."}
```
